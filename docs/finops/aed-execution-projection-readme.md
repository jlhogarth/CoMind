# Private AED reconciliation

FinOps owns this read-only report under issue #550 and draft PR #551. AED-007 owns the three reused scripts, collection, monitoring, ingestion and recovery under issue #540 and draft PR #541. This is T1 reversible Test development. It creates no database objects, credentials, policies, billing receipts or Production deployment. The authorized private Drive writeback is a T2 recordkeeping action kept outside the API receipt ledger.

## Operator workflow

1. In a read-only transaction through the existing authorized private SQL connection, execute [the projection](aed-execution-readonly-projection.sql). Save the complete returned array of rows as a private JSON file. For a client that returns one object per row, convert its result to an array. Never export raw payloads to this report.
2. Obtain the AED-007 tools from the verified [PR #541 commit](https://github.com/jlhogarth/CoMind/tree/32d19fc955b9620db5c3ddcfadb8420362bf9cdb/server/scripts). The bridge verifies the pinned bytes before executing them. The dependency is explicit while the AED lane remains separate. The normal default test path is `server/scripts` once the reviewed dependency is available there.
3. Run `python scripts/finops_aed_reconciliation.py --help` for inputs. Pass `--projection-json` the private query result. For each archive, pass `--aed-tools` the verified script directory and `--proof` the local archive path, its SHA-256 from the independent provenance record, and its authorized private source reference. Supply the tools directory once when passing multiple proofs. Set `umask 077` and redirect the JSON output to a private destination. The CLI exits on the first invalid input without emitting a partial report. Without proofs, it still reports the Supabase rows with no observed account meter.
4. Keep output in the authorized private workspace or Drive structure. The report is queryable JSON and does not run a public service. It contains account readings and their provenance links. Keep those out of GitHub.

The bridge checks the archive SHA-256 and every manifested member. It reuses AED-007 to verify the execution identity, contiguous events, snapshot hashes, timing and sidecar digest, and to regenerate the AED report. A matching persisted row must also have verified sequence and hash coverage plus identical execution ID, source digest, event count and execution boundaries. Archive-only runs are explicitly marked outside Supabase. Shared-account windows that overlap or reuse a snapshot are refused as ambiguous. The Supabase artifact hash identifies the stored monitor artifact. The separate archive hash identifies the proof ZIP that was independently verified. Matching execution identity and source digest bind these evidence sources even when the packaging differs. Missing readings and balance increases do not produce consumption values. The historical alternate SQL file `aed_execution_evidence_projection.sql` predates this bridge and remains a reference.

The JSON separates measured process and FlowOps bytes from account-meter movement. Account differences are observed and unallocated. The projection reports AED cost-evidence coverage and keeps actual and estimated USD null until a verified financial source exists. A provider tag alone does not establish billing. SQL token totals include reporting terminal steps only and may represent partial telemetry. The private report suppresses token and duration totals for incomplete event sequences. A runtime model is unavailable in the current AED event contract.
