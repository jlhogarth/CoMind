# IIC-007: Cross-system evidence integration, first read-only adapters

## Authority and reuse
T1 reversible, Test-only repository code and CI. GitHub Actions remains authoritative for workflow outcome and exact SHA; the private Supabase Test RunBook view `comind_pm.v_runbook_lane_state` remains authoritative for its projected historical lane-state field. The adapter consumes caller-fetched records and makes **no** requests or writes. Read permissions, scope, and source authenticity must be established independently by the caller; arbitrary JSON input never grants trust or authority.

## Evidence envelope
A normalized record includes source system/authority, canonical object identity, claim type/value, explicit environment, source recorded time, read observation time, exact source revision, evidence reference, deterministic input record SHA-256, explicit freshness deadline, current/stale/unspecified classification, epistemic status, and provenance. An absent freshness boundary produces `uncertain`, never fabricated currency. Contradictory values for the same scoped claim remain `mixed` with each source record preserved. Stale input is not silently successful.

Contextual validation of source authenticity and scope remains mandatory before use in an acceptance decision.
