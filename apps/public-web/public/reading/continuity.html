Research direction / Memory

Cognitive continuity

A system that remembers more is not automatically more helpful. The useful question is which context should persist, how it should change, and when it should be forgotten.

Public research overview · An exploration of questions and design principles, not a published paper or product claim.

The problem of starting over

Long-running work contains goals, decisions, corrections, and unresolved questions. When that context disappears between sessions, people spend time rebuilding it and may repeat a discarded approach. A durable memory can reduce that friction, but only if it stays connected to the original evidence.

A practical way to think about memory

Consider three layers: a record of what was said or done; a working interpretation of what matters now; and a person’s current choice about what should happen next. The record should not silently turn into a permanent belief. Interpretations need dates, provenance, and an opportunity for correction.

Example

“Use Cloudflare for the public preview” is a decision in a specific project. It should not become a universal rule for every CoMind service.

The central tension

Too little memory causes repeated work. Too much unexamined memory preserves stale assumptions and can expose information beyond its intended audience. A useful system asks whether a memory is relevant, current, authorized for this context, and still supported by evidence.

Questions for further research

  • How should a system notice that a decision has been superseded?
  • What should a person be able to inspect, correct, or delete?
  • How can uncertainty travel with a memory into later reasoning?
