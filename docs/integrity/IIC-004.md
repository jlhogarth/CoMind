# IIC-004 Canonical Integrity Registry

## Purpose

IIC-004 creates one canonical machine-readable registry for CoMind hard implementation-integrity controls. The registry records what each control means, what actually exists, its current maturity, its enforcement posture, and reviewed finding dispositions without converting review records into scanner suppression.

The governing invariant remains: the observable representation of the system must not materially exceed verified implementation reality.

## Authority model

`config/integrity-registry.v1.json` is the canonical repository representation of control definitions and maturity state.

It is not:

- a replacement for source evidence;
- an automatic suppression list;
- a database authority for runtime state;
- permission to promote a control merely by editing a state string;
- a substitute for CI, runtime, or exact-head acceptance evidence.

Promotion history and reviewed finding records must cite evidence. Scanner output remains independently visible.

## Maturity model

The ordered states are:

`DEFINED -> SHADOW -> PROVEN -> ENFORCED -> GOVERNED`

- `DEFINED`: the control contract exists, but no detector is claimed.
- `SHADOW`: an implemented detector runs without blocking acceptance.
- `PROVEN`: the detector has survived real development and reviewed classification evidence but remains nonblocking.
- `ENFORCED`: qualifying findings block the CoMind acceptance boundary.
- `GOVERNED`: enforcement plus durable exception, ownership, promotion, and evidence governance is fully bound.

The validator rejects backward maturity history and requires current state to equal the final promotion-history state.

## Truthful initial state

At IIC-004 introduction:

- NPH-001 No Placeholder: `ENFORCED`, represented as the existing external repository checker;
- NDT-001 No Dead Path: `ENFORCED`, implemented by the IIC engine and IIC-003 enforcement contract;
- NFS-001 No False Success: `PROVEN`, implemented by the IIC engine but candidate-only and nonblocking;
- all remaining cataloged controls: `DEFINED`, with detector kind `none` and no accepted-verification claim.

This distinction prevents the catalog itself from masquerading as implementation.

## Reviewed finding records

The four NFS-001 candidates reviewed in IIC-002 PR #346 are recorded by exact stable fingerprint with:

- source path and target;
- `accepted-pattern` disposition;
- rationale;
- evidence source;
- explicit reconsideration trigger.

They remain scanner findings. Registry classification does not remove them from machine evidence.

## Validation invariants

`scripts/validate_integrity_registry.py` rejects at least:

- malformed or duplicate control IDs;
- unknown maturity states;
- backward promotion history;
- maturity/history disagreement;
- a `DEFINED` control claiming an implemented detector or accepted verification;
- an implemented/proven control without detector paths or verification evidence;
- missing detector files;
- `ENFORCED` state without blocking behavior;
- pre-enforcement states claiming blocking behavior;
- malformed or duplicate reviewed finding fingerprints;
- reviewed findings for unknown or definition-only controls;
- accepted patterns without rationale/evidence/reconsideration data;
- silent downgrades of the established NPH/NDT/NFS foundation.

## Workflow binding

The existing `Integrity Governance` workflow now runs both registry validation and adversarial registry tests in addition to the IIC-003 enforcement contract checks.

No separate registry CI authority is introduced.

## Database decision

No database table is created in IIC-004. Repository JSON is sufficient for a small versioned control catalog and reviewed classifications, and it keeps changes reviewable with code. Existing CoMind evidence systems remain the durable authority for development evidence. A database projection can be added later only if operational querying or cross-system integration demonstrates a real capability gap.

## Recovery

Revert the registry/validator/workflow changes. No runtime or database rollback is required.
