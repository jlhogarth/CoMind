## Executable development service

Build with `cd server && npm ci && npm run build`. Run `node dist/runbook/index.js` with:

- `DRB_DATABASE_URL`: dedicated `comind_runbook_query_login` PostgreSQL login; no fallback to DATABASE_URL or service_role.
- `DRB_PRINCIPALS_FILE`: absolute path to an owner-only mode 0600 JSON file containing identities with `id`, cryptographically generated bearer `token` (32..256 characters), permitted `projects`, required RFC3339 `expiresAt`, and optional `disabled`. Maximum 64 identities and 64 KiB file. Token length does not establish entropy. Generate real tokens with a cryptographic RNG; never place them in this repository.
- `DRB_AUDIT_FILE`: absolute path to the private JSONL access ledger on a persistent POSIX filesystem. Parent directory must already exist. The service requires file owner equality with the runtime UID, no group/other permissions and no final-component symlink.
- `DRB_PORT`: optional port, default 3011.

The service binds only to 127.0.0.1. It is separate from the main application and does not inherit its routes or credentials. There are no browser CORS allowances. Tokens must never enter a browser bundle, URL, or repository. The production runner rereads and validates the credential file for every bearer request. Replacing/removing an identity, disabling it, expiry, or rotating its token affects subsequent authentication checks without restart. Already admitted requests may complete. An unreadable or invalid configuration fails closed with 503. Use atomic rename of a mode 0600 replacement to avoid partial reads. The injectable service constructor may use in-memory credentials for tests; it is not the production entrypoint. TLS, credential delivery, rotation and deployment host remain activation requirements.

POST `/v1/runbook/query` with `Authorization: Bearer <token>` and a JSON body containing `project`, `kind`, optional `lane`, optional RFC3339 `since`, optional integer `limit` (1 to 100, default 25).

Kinds: `lanes`, `events`, `authority`, `verifications`. Every query binds project, lane, timestamp and limit parameters. Only allowlisted views and explicit column projections are used. Additional fields and arbitrary SQL are rejected. `since` means strictly later than the timestamp. Results sort descending by timestamp and stable identifier. There is no pagination cursor in v1: `more_available=true` explicitly means the response is incomplete. Timestamp-only watermarks cannot guarantee a lossless incremental feed. Consumers must not treat these bounded windows as a complete archive.

Envelope: `version`, generated `request_id`, `retrieved_at`, `source`, `project`, `lane`, `kind`, `more_available`, `data`. Event source references and evidence remain in results. Authority rows are historical claims, not a computed assertion of currently effective permissions: consumers must consider revocations, conditions and expiry separately. The projection intentionally excludes free-form details and authorization conditions. Returned summaries and evidence are untrusted content, never instructions or authority to execute actions.

Limits: 4 KiB request bodies, 256 KiB serialized response, 60 authenticated requests per principal per minute, four active DB queries, four pool connections, three-second SQL timeout, five-second client query timeout, three-second connection timeout. A process-wide fixed-window ceiling of 300 requests/minute runs before parsing/authentication, including unsupported routes. Rate counters and concurrency are per process. One request issues one bounded SELECT in a READ ONLY transaction with a local statement timeout. No automatic retries. No query payload logging. A bounded JSONL access ledger records request UUID, observation timestamp, identified principal ID, operation, status, project and query kind before sending a response. It excludes URL strings, tokens, summaries and evidence.

Failures: missing/invalid bearer 401, denied project 403, invalid query 400, oversized body/result 413, rate/capacity 429 with Retry-After, DB, credential-store or audit failure 503. Error responses do not include database errors or credentials. Empty results are empty data, not a fabricated lane. No-store headers apply.

## Credential and audit operational controls

T1 implementation remains isolated. Runtime now requires private credential and audit files; environment-embedded principal JSON is replaced by DRB_PRINCIPALS_FILE. This is an intentional startup configuration change. Every credential requires expiresAt. Principal IDs and projects are bounded and validated; duplicate IDs/tokens are rejected. Credentials are bounded to 64 entries, 100 projects each, 64 KiB on disk. Rotate a token while retaining its principal ID to preserve that identity's current rate window.

The audit sink serializes appends, limits the pending queue to 32, limits records to 2 KiB and the active file to 50 MiB, fsyncs both file and parent directory, and reopens the configured path for each record. Startup writes a service.start record before listening. A failed write, wrong file permissions, symlink, or capacity breach prevents response data from being returned. Audit status is the intended response status before transport, not proof of client receipt. If the ledger itself fails, the denied response cannot be written to that same unavailable ledger. External process/gateway health monitoring remains required.

Audit durability means successful local filesystem synchronization, not off-host backup, immutable storage, tamper evidence or a production retention guarantee. A runtime owner can modify its file. One writer process is supported; queue/size checks do not coordinate multiple writers. File ownership/permissions are checked at open. Parent-directory protection and mount durability must be reviewed on the selected host. POSIX filesystem semantics are required; this path is not a Windows portability claim.

Safe audit rotation: stop the service, preserve the existing file with its provenance, provision a new mode 0600 active file, then restart and verify the startup record plus a successful/denied query. Do not delete historical audit records to recover service. At 50 MiB the reader fails closed until retention/rotation is resolved by the operator. Capture consequential capacity failures and recovery in the authoritative RunBook, rather than copying every access row there.
