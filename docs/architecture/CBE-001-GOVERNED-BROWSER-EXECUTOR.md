# CBE-001 Governed Browser Executor

Status: accepted Test substrate, pending merge
Production change: false
Issue: #449
PR: #450

## Purpose
CBE supplies a self-hostable browser execution substrate for CoMind. It is not an authority source. L4A, RuleBook, CLEAR, canonical Foundry leases, and human authority remain authoritative.

## Flow
CoMind controller -> bounded browser job -> policy/CLEAR -> Foundry lease verification -> Playwright worker -> Chromium -> allowlisted target -> redacted evidence.

## Invariants
- Deny navigation outside explicit host allowlists.
- Require HTTPS and reject credentials embedded in target URLs.
- Bound every job by identity, caller, canonical lease reference, expected result, and timeout.
- Validate the task, lease token, worker identity, fencing epoch, and expiry against `comind.cm_foundry_work_lease` before browser execution.
- Require authority reference and CLEAR approval before consequential browser actions.
- Never emit passwords, cookies, tokens, MFA material, browser storage state, raw authorization material, or lease tokens into canonical evidence.
- Strip URL query strings and fragments from canonical browser evidence.
- Browser UI access never expands caller authority.
- Production activation is excluded from CBE-001.

## Dependency decision
Playwright is the preferred browser library. CBE-001 pins `playwright` 1.64.1 from a successful Node 24 package-manager bootstrap. The committed dependency state is generated by npm and not hand-authored. Playwright supports browser automation scripts and Chromium. Its package is Apache-2.0 licensed, and current official system requirements include Node 24.

## Worker contract
CBE-001 executes `navigate`, `read`, and `screenshot`. The policy model also recognizes `click`, `type`, `download`, and `upload`, but the worker rejects those actions as unbound in CBE-001 even when CLEAR is present. This is intentional. It prevents the first browser slice from becoming an implicit mutation authority.

Screenshot bytes are not placed in canonical evidence. The worker emits only screenshot SHA-256 and byte length. Browser response evidence is bounded to final URL, title, status, HTTP success state, and screenshot metadata.

## Persistent context
The Playwright driver supports an isolated persistent Chromium context directory. The path and browser storage state are never included in evidence. The canonical Foundry lease remains the concurrency fence for a browser job using that context.

## Failure semantics
Browser startup, navigation interruption, timeout, cleanup failure, and lease-verification infrastructure failure are explicit bounded failed/recoverable states. Policy rejection, invalid lease state, and expected-result mismatch are explicit non-recoverable outcomes for the submitted job.

## Integration proof
The dedicated GitHub Actions workflow installs committed dependencies with Node 24, verifies the Playwright pin, installs Chromium and system dependencies, builds the server, runs deterministic CBE tests, launches the governed worker against `playwright.dev`, and launches the same governed worker against the public CoMind GitHub repository. Both browser runs use persistent-context mode and emit redacted evidence artifacts.

The GitHub Actions proof uses an isolated synthetic valid-lease verifier because CI has no live CoMind database connection. The canonical Foundry lease verifier is tested independently against the exact `comind.cm_foundry_work_lease` contract.

CBE-001 also has a real GitHub Codespaces runtime proof. A dedicated proof-only Codespace used the pinned `mcr.microsoft.com/playwright:v1.64.1-noble` image and executed the governed CBE worker inside GitHub Codespaces. The job used L4A authority reference `L4A-CBE-001-Test`, navigated to the public CoMind GitHub repository, required HTTP success and final host `github.com`, returned HTTP 200, and emitted bounded screenshot evidence as SHA-256 plus byte length. The durable proof is stored at `docs/provenance/2026-10-31-cbe-001-codespaces-runtime-proof.json`.

Authentication was not required for this public Test target. Therefore the CBE-001 acceptance clause requiring Joseph to authenticate when authentication is required was not triggered. The private noVNC persistent-context harness remains available for later jobs that genuinely require human authentication, but it is not required to close CBE-001.

## Associated CDP observation path
The browser architecture keeps Playwright as the control plane and Chrome DevTools Protocol as a separate observation plane for later CFR-002 work. CDP can capture Network, SSE, and WebSocket traffic for raw append-only capture, normalization, reconciliation, and drift detection. That observation plane is not required for CBE-001 acceptance. Any future debug endpoint must remain local-only and must not expose a public Chromium debugging port.

## AED-002 relationship
CBE-001 is a bounded infrastructure diversion. It does not supersede AED-002. Once this browser slice is merged, AED-002 can use CBE as an execution option without changing AED-002 authority or acceptance semantics.
