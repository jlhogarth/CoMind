# IIC-005 NMC-001 No Magic Configuration

## Purpose

IIC-005 introduces NMC-001 No Magic Configuration as a conservative shadow control without weakening NDT hard enforcement or rewriting feature-lane code.

## Detection scope

NMC-001 reports review candidates only for runtime source where configuration appears materially operational and statically embedded.

Current candidate classes:

1. consequential environment variables with literal fallback values, limited to names indicating URL/URI, host, port, model, provider, environment, timeout, retry, authority, purpose, endpoint, or region;
2. literal HTTP or HTTPS endpoints only in connection-oriented runtime contexts such as `baseUrl`, endpoint, service URL, API URL, request URL, or fetch usage.

The connection-context restriction was added after the first real scan proved that ordinary Console navigation links and provenance-source URLs were false-positive noise rather than operational configuration.

## Exclusions

The detector intentionally excludes:

- tests and test directories;
- fixtures;
- documentation;
- repository scripts;
- generated/build output;
- configuration files whose purpose is already explicit configuration ownership;
- non-operational environment fallbacks;
- required environment variables with no literal fallback;
- navigation links and provenance/documentation source URLs without connection semantics.

A candidate is not a violation. Review determines whether a literal is an intentional canonical default, a test/development boundary, or hidden operational configuration.

## Real repository evidence

The first exact-head scan emitted 13 NMC candidates. Review showed that nine were ordinary Console navigation links and one was a pricing/provenance source URL. The detector was narrowed rather than suppressing fingerprints.

The refined exact-head scan emitted three candidates:

- SDN default port 3100;
- ordinary database purpose `application`;
- local Ollama loopback endpoint.

All three are reviewed `accepted-pattern` values with explicit reconsideration triggers in the canonical Integrity Registry. They remain visible NMC scanner findings.

## Enforcement boundary

NDT-001 remains hard enforced by `check_implementation_integrity.py`.

NFS-001 remains candidate-only within the core engine.

NMC-001 writes a separate machine-readable shadow evidence file through the same Implementation Integrity workflow. NMC findings report `blocking_count: 0` in this increment.

## Registry maturity

NMC-001 is promoted from `DEFINED` to `SHADOW` only after refined exact-head evidence exists. The registry cites the exact scan run and records the three reviewed findings by stable fingerprint.

No further maturity promotion is claimed by IIC-005.

## Remediation ownership

IIC-005 does not rewrite runtime configuration in feature lanes. If a future candidate is reviewed as a genuine defect, remediation belongs to the owning lane or a separately scoped issue after collision review.

## Recovery

Revert the NMC detector, tests, workflow additions, reviewed registry records, and NMC maturity promotion. No runtime or database rollback exists.
