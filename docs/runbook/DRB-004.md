# DRB-004 Live RunBook monitoring in CoMind Test

[Issue #555](https://github.com/jlhogarth/CoMind/issues/555) extends the [DRB-003 rules](./DRB-003.md). CoMind's existing RunBook ledger remains the evidence authority. The worker reads one configured Google Doc through an explicitly configured, federated Google Viewer identity. The request selects tab IDs and structural end indexes, including nested tabs. Google only provides the Docs revision ID to editors. A Viewer can measure size and the rollover rule blocks readiness when the revision is unavailable. The scheduler does not attempt a cutover.

## Test deployment and acceptance

1. Verify the operator-selected Doc and provision its dedicated federated Google service account with Viewer access. Store the reviewed external-account configuration through the existing Test host's secret or file provisioning path. Keep the document identifier in private runtime settings. Configure the backend with `DRB_RUNBOOK_GOOGLE_DOC_ID`, `DRB_RUNBOOK_GOOGLE_CREDENTIALS_FILE`, and `DRB_RUNBOOK_DATABASE_URL`. The connection must be scoped to the Test database, use verified TLS and the dedicated `comind_runbook_scheduler_login` identity, and have only the privileges required for the due-slot function and the existing canonical writer. The backend owner must attest the credential and host before setting `DRB_RUNBOOK_SCHEDULER=test`.
2. Apply `20261110_001_drb_004_live_runbook.sql` only to CoMind Test and run its companion verification. The migration adds an independent due-slot calculation and a bounded Console projection over existing receipts. It adds no table or public data grant. An ordinary client cannot call either function.
3. Configure an existing protected Operator Console Test deployment with `DRB_RUNBOOK_CONSOLE=test` and the same `DRB_RUNBOOK_GOOGLE_DOC_ID`. It requires the server-side trusted-perimeter binding already used for Continuous Excellence. Verify denial outside that perimeter. The route is `/runbook` under the **RunBook Health** navigation item.
4. Verify a worker-created receipt, including the exact due slot and observed time, then verify that the authenticated Console shows the same scheduled receipt. The worker checks on startup and at 15-minute intervals. The database uses Monday at 9 a.m. Indianapolis time with a 30-minute grace period. A catch-up receipt remains visibly late. Retries return the first durable receipt for the due slot. A manually measured receipt has its own namespace and cannot satisfy the scheduler check.

The scheduler and Console settings are opt-in. Disable both settings to roll back activation without removing historical evidence. Keep the existing ChatGPT watch until a genuine scheduled run is independently verified. A Test probe performed through connected tools provides source-to-ledger evidence while the host and workload identity are being bound. It is labeled manual in the status projection.

## Hosted Test evidence

On November 10, 2026, a manual structural read of the actual Development Runbook produced **338,884 UTF-16 units**. The application evaluator recorded a review-threshold result and blocked rollover. The existing canonical Test ledger accepted receipt `cc882720-8bed-4937-965f-171f50b1d33f`. A separate hosted read using the `service_role` status projection returned the same receipt as a manual probe and reported the November 9 scheduled slot as missed. The migration verification confirmed that ordinary client roles cannot execute either new function.

The hosted scheduler and protected Console still need deployment bindings. The existing Test database has no dedicated RunBook scheduler login. The available Vercel Console project exposes no configured Continuous Excellence server credential, and the older Railway Console deployment is removed. The Google connector read was performed under the existing connected user identity. A federated Viewer identity on the selected Test scheduler host remains unverified.

## Source evidence

- [Google Docs documents.get](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get) specifies the read-only scope and tab content option.
