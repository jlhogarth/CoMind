# DRB-003 RunBook lifecycle checks

[Issue #552](https://github.com/jlhogarth/CoMind/issues/552) owns this isolated Test slice. The [Durable RunBook](./DRB-002.md) supplies the existing evidence boundary. [CFR-001E](https://github.com/jlhogarth/CoMind/pull/184) supplies the separation between retention eligibility and an authorized action.

| Rule | Enforcement in the isolated Test path | Proof |
| --- | --- | --- |
| DRB-LIFECYCLE-001 | Count approximate UTF-16 units across unique content tabs. Flag 300,000 for review and 750,000 for escalation. | Inclusive boundaries, multiple tabs, invalid input and escalation receipt. |
| DRB-LIFECYCLE-002 | The independent status command checks the exact due slot. Report missed, measurement failure, policy change or current. | Missing slot, failed read, policy change, and replay with one durable receipt. |
| DRB-LIFECYCLE-003 | Require measurement, a matching source revision, and evidence for the milestone, archive, handoff and verified writer inventory. A passing result is readiness for review. | Stale and wrong document revisions, missing evidence, and unverified or duplicate writers. |
| DRB-LIFECYCLE-004 | Classify supplied records as review candidates or block them on missing evidence, protected classification, holds, or an unexpired window. | Protected and unknown classes, missing evidence, holds and retention-window boundaries. |

The versioned rule inventory lives in `server/src/runbook/lifecycle.ts`. CoMind RunBook operations owns the policy. Input evidence is synthetic in this slice. The fixture reader checks the structure and revision binding of evidence supplied to it. A future live adapter must verify referenced evidence against its authoritative source and check the current revision again at cutover.

The check writes to `comind_pm.record_runbook_event` with the `runbook_lifecycle_test` source. The first committed receipt for a document and due slot is authoritative for that slot, including a failed measurement. Replaying that slot returns its receipt. A transaction-scoped lock serializes concurrent record attempts. An unavailable ledger produces a command failure and a later independent status probe can report the missing receipt. Schedule, grace period, alert delivery and due-slot selection belong to the calling runtime.

## Run in isolated Test

Build with `cd server && npm ci && npm run build`. Use a fresh disposable PostgreSQL 17 database named `drb_test` on 127.0.0.1. The existing [DRB integration test](../../server/test/runbook-query.integration.test.mjs) applies the existing schema, verifies the real receipt and duplicate protection, and exercises both command paths. Run it with `DRB_TEST_ADMIN_URL` set to that database and `node --test test/runbook-query.integration.test.mjs` from `server`.

The application commands are `node dist/runbook/lifecycle-cli.js check <volume-id> <scheduled-utc> <fixture.json>` and `node dist/runbook/lifecycle-cli.js status <volume-id> <scheduled-utc>`. The due slot uses UTC ISO 8601 with milliseconds. The synthetic fixture contains `snapshot`, an optional `plan`, and an optional array of `retention` records. Use the integration test for a working fixture. The CLI accepts only the dedicated disposable loopback database and returns exit status 2 for a missed, invalid or unavailable evaluation.
