# DRB-004 Live RunBook monitoring in CoMind Test

[Issue #555](https://github.com/jlhogarth/CoMind/issues/555) extends the [DRB-003 rules](./DRB-003.md). CoMind's existing RunBook ledger remains the evidence authority. The worker reads one configured Google Doc through an explicitly configured, federated Google Viewer identity. The request selects tab IDs and structural end indexes, including nested tabs. Google only provides the Docs revision ID to editors. A Viewer can measure size and the rollover rule blocks readiness when the revision is unavailable. The scheduler does not attempt a cutover.

Set the repository variable `DRB_RUNBOOK_SCHEDULER=test` only after the Google identity, document ACL, and database secret readbacks pass.

A manual probe cannot satisfy scheduler acceptance.

Keep the ChatGPT Health Watch until a genuine scheduled run is independently verified. No continuously running worker is required for this weekly check.

## Hosted credential activation

The hosted-role migration adds a private binding for the selected RunBook and two dedicated Test logins. The scheduler may read and append scheduled receipts for that bound volume and due slot through fixed database functions. The Console login may read the bound volume's status projection. Neither login receives access to the underlying evidence tables.

The one-shot GitHub Actions job authenticates the dedicated Google Viewer using its workflow-specific OIDC provider. It receives `DRB_RUNBOOK_GOOGLE_CREDENTIALS_FILE` from the Google auth action and reads the bound Doc without a long-lived Google key. The staged Railway service is not deployed and must remain off to avoid a second scheduler.

The GitHub job and protected Console preview each require `DRB_RUNBOOK_DATABASE_CA` with the Supabase root CA pinned by CoMind CI. Their separate scoped Test database connections validate the server certificate and hostname.

The protected Vercel preview uses `DRB_RUNBOOK_CONSOLE_DATABASE_URL` and the scoped Console login. The two runtime switches `DRB_RUNBOOK_CONSOLE=test` and `DRB_RUNBOOK_CONSOLE_ACCESS=trusted-test-perimeter` apply only on the verified protected preview. Enable deployment protection before configuring these values.
