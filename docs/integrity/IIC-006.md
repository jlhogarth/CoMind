# IIC-006: Retry and cleanup integrity | Test-only implementation

## Authority and architecture
T1 reversible repository development under the Development Environment Contract v1.4. Canonical owners remain Foundry (leases, fencing and retries), Lane Health Sentinel (bounded retry), MDO (planning retries), Continuous Excellence (recovery), and RunBook (durable history). IIC does not execute retries, clean resources, grant authority, persist canonical task state, or mutate feature-lane behavior.

## Static detector contract
The Python standard-library detector scans literal GitHub Actions `run` bodies and `package.json` scripts. NRC-001 flags `gh run rerun` and non-finite/non-literal `curl --retry` counts for contextual review; a positive literal `curl --retry` count of at most 10 is treated as statically bounded, **not as globally safe**. NCI-001 flags `mktemp -d` and detached `docker run -d` commands lacking a syntactically visible cleanup token in the same block. This deliberately does not claim lifecycle truth across separate steps or runtime modules. Source code, other languages, nested shell semantics, and external compensation are outside the first detector scope.

All emitted records are `candidate` with stable fingerprint, path, line, evidence, observed local controls, and explicit limitation. No findings are automatically accepted, blocked, suppressed, or treated as verified risks. Missing outcomes and incomplete static coverage are not success.

## Integration and acceptance
The existing Implementation Integrity workflow retains NDT hard enforcement, NFS review, and NMC shadow detection. It additionally runs IIC-006 synthetic tests, emits a dedicated machine-readable shadow artifact and displays its content. Registry entries are upgraded to SHADOW only when their code and workflow are present. Findings are visible and require contextual owner-lane review, not remediation in this PR.

Synthetic tests cover retry/cleanup positive, finite-bound negative, dynamic/ambiguous, comments, stable fingerprints, scanned workflow/package scripts, and execution failure. Real repository scan counts must be inspected from the exact-head artifact before merge.

## Forward impact and recovery
Direct effect is additional CI read-only analysis; second-order effect is potential false-positive review overhead, mitigated by shadow mode and no feature-lane mutation. No database, secrets, Production, paid model, security control, or public endpoint changes. Revert the IIC-006 commit to restore the previous state. Approval boundary for any future change to runtime behavior or hard enforcement remains independent.
