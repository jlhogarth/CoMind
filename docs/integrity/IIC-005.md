# IIC-005 NMC-001 No Magic Configuration

## Purpose

IIC-005 introduces NMC-001 No Magic Configuration as a conservative shadow control without weakening NDT hard enforcement or rewriting feature-lane code.

## Initial detection scope

NMC-001 reports review candidates only for runtime source where configuration appears materially operational and statically embedded.

Initial candidate classes:

1. consequential environment variables with literal fallback values, limited to names indicating URL/URI, host, port, model, provider, environment, timeout, retry, authority, purpose, endpoint, or region;
2. literal HTTP or HTTPS endpoints in runtime source.

## Exclusions

The detector intentionally excludes:

- tests and test directories;
- fixtures;
- documentation;
- repository scripts;
- generated/build output;
- configuration files whose purpose is already explicit configuration ownership;
- non-operational environment fallbacks;
- required environment variables with no literal fallback.

A candidate is not a violation. Review must determine whether a literal is an intentional canonical default, a test/development boundary, or hidden operational configuration.

## Enforcement boundary

NDT-001 remains hard enforced by `check_implementation_integrity.py`.

NFS-001 remains candidate-only within the core engine.

NMC-001 writes a separate machine-readable shadow evidence file through the same Implementation Integrity workflow. NMC findings always report `blocking_count: 0` in this increment.

## Registry promotion discipline

The canonical Integrity Registry remains NMC=`DEFINED` until the first real exact-head NMC scan is produced and reviewed. After evidence exists, the same PR may promote NMC to `SHADOW` and cite that exact evidence. This prevents the registry from claiming accepted implementation before acceptance evidence exists.

## Remediation ownership

IIC-005 does not rewrite runtime configuration in feature lanes. If a candidate is reviewed as a genuine defect, remediation must occur through the owning lane or a separately scoped issue after collision review.

## Recovery

Revert the NMC detector, tests, workflow additions, and later registry promotion. No runtime or database rollback exists.
