# IIC-008: Implementation Reality Graph

## Purpose and authority
T1 reversible, read-only Test implementation. Implements the first deterministic claim/evidence projection using IIC-007 envelopes and the canonical Integrity Registry, not a new database, model-based truth judge, authorization evaluator, or runtime agent. GitHub, RunBook, ThreadKeeper, Foundry, RuleBook and human approvals retain their original ownership.

## Graph model and semantics
`config/integrity-reality-graph.v1.json` records the node/edge taxonomy. Typed nodes capture claims, revisions, configuration contracts, CI, runtime outcomes, artifacts, documentation, explicit authority, environments, dependencies, controls and findings. Edges retain explicit evidence provenance and source environment; no implicit promotion from documentation, source status or a registry control to a broader claim.

Each claim specifies a narrow expected `claim_type`, `claim_value`, environment and explicit `authority_required`. A verified, current, same-environment matching evidence binding may support only that exact narrow claim. Contradictions are `contested`, missing/uncertain/stale/wrong-environment evidence remains `unresolved`. Consequential claims requiring authority cannot become supported without a separate, explicitly supplied verified approval scoped to the claim and environment. The graph never creates approval.

## Input and execution
Run `scripts/integrity_reality_graph.py` with JSON files for `--envelopes` (IIC-007 output), `--claims`, `--bindings`, `--approvals`, and `--registry` (canonical registry v1). These are operator-supplied source-bound records, not trusted merely because JSON parses. The tool performs no HTTP/database access and has no credentials. Graph output includes nodes, edges, per-claim status and inspectable path edges. This v1 projection does not create a persistent graph store or Operator Console route.

## Testing and real-source acceptance
Synthetic tests exercise agreeing, conflicting, stale, missing, cross-environment, unverified/missing human authority, duplicate evidence, registry control linkage, and documentation-overclaim paths. A separate bounded acceptance should process the live-source-derived IIC-007 envelopes and produce at least one real CoMind capability claim with traceable evidence and explicit authority posture. An unresolved result is acceptable when evidence is insufficient; inventing support is not.

## Forward impact, cost, recovery
No Production activation, migration, RLS/grant, provider billing, live source mutation or authority expansion. Additive CI read-only CPU only. Revert this branch to remove projection without changing source evidence. No exceptions.
